# GitHub Issues workflow

Чатопс-процесс для работы с GitHub Issues. GitHub остаётся внешней системой;
каждая запись должна указывать целевой репозиторий и issue, а результат
проверяется чтением обратно.

Для комментариев в репозиториях, которыми владеет TeaShaman-cyber, используй
прямой `gh issue comment` в рамках текущей задачи: предварительная карточка и
отдельное одобрение каждого комментария не нужны. Карточка — необязательный
черновик для сложных/высокорисковых записей, новых issues или внешних
репозиториев. Никогда не помещай в карточки и комментарии токены,
auth-настройки или секреты.

## Контур

```text
owned-repo comment:
explicit --repo/issue -> inspect body/thread and duplicates -> gh issue comment
                      -> read back the exact comment

complex/high-impact/external write:
optional card -> inspect -> draft -> approval when required
              -> one external action -> read-back
```

## Правила

- В репозиториях TeaShaman-cyber любой комментарий в рамках текущей задачи
  можно отправить напрямую через `gh issue comment --repo ...`; предварительная
  карточка и отдельное одобрение комментария не нужны.
- `issue-guard` может требовать записать наблюдение и вывод в issue перед
  продолжением исследования. Сам комментарий удовлетворяет этому требованию;
  карточка не является обязательной предпосылкой.
- Перед комментарием прочитай issue и обсуждение, проверь отсутствие дубля.
  После записи перечитай точный комментарий и сверь репозиторий, issue и URL.
- Для создания issue, закрытия, высокорисковой правки или записи во внешний/
  upstream-репозиторий требуется соответствующее явное одобрение. Карточка
  может применяться для сложной или неоднозначной операции, но не обязательна
  для комментариев в наших репозиториях.
- Явный `--repo` обязателен: текущий checkout или `origin` не выбирают target
  автоматически.
- Ошибка или несовпадение read-back останавливает запись; автоматических
  повторов и обхода auth-маршрута нет.
- GitHub launcher/wrapper отвечает за auth и транспорт. В комментарии нельзя
  помещать токены, auth-настройки или секреты.

## Необязательная карточка

Карточка и `issue_card_guard.mjs` — вспомогательный маршрут, не обязательный
этап и не автоматический гейт в рантайме. Для любого комментария в
репозитории TeaShaman-cyber
используй прямой `gh issue comment`; карточку не создавай и не валидируй.
Карточки остаются опциональными для новых issues, высокорисковых изменений
состояния, внешних/upstream repos или когда карточку явно просит пользователь.

## Статусы карточки (только если карточка выбрана)

```text
DRAFT -> READY_FOR_REVIEW -> APPROVED -> EXECUTED -> READ_BACK_VERIFIED
                              \-> REWORK
                              \-> BLOCKED
```

Когда карточка используется, `APPROVED` означает одобрение конкретного текста
и операции, а не постоянное разрешение на будущие действия.

`repository_source` и `target_confirmation` — поля только необязательной
карточки. Для прямого комментария в своём репозитории достаточно явных
`--repo`/issue и read-back; карточные поля не требуются.

## Граница текущего шага

Этот документ задаёт два маршрута: прямой комментарий в репозитории-владельце
с явным `--repo` и чтением результата обратно; необязательную карточку для
сложной, высокорисковой или внешней записи. `issue-guard` остаётся отдельным
гейтом: он требует оставить наблюдение в issue, а не подготовить карточку.
