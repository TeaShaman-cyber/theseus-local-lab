# GitHub Issues workflow

Чатопс-процесс для работы с GitHub Issues. GitHub остаётся внешней системой,
а карточка — локальным черновиком и журналом намерения. Карточка не содержит
токенов, auth-настроек или секретов.

## Контур

```text
issue/card -> inspect -> draft -> local-check -> human-review
           -> explicit-approval -> one external action -> read-back -> close
```

## Правила

- Любая запись во внешний GitHub требует отдельного явного одобрения в чате.
- Одобрение процесса не является одобрением конкретного комментария, edit,
  label, close или другой операции.
- До одобрения разрешены только чтение, поиск дублей, подготовка черновика и
  локальная проверка.
- После операции обязательна проверка read-back: репозиторий, issue, операция
  и фактический результат должны совпасть с карточкой.
- Целевой репозиторий и текущий checkout — разные поля. `origin` текущего
  workspace не выбирает target автоматически.
- Ошибка или несовпадение read-back останавливает карточку; автоматических
  повторов и обхода auth-маршрута нет.
- GitHub launcher/wrapper отвечает за auth и транспорт. Карточка не знает,
  где лежит токен и как он извлекается.

## Минимальная карточка

Шаблон находится рядом в `docs/plans/github-issue-card.md`. Для одной карточки
должна быть ровно одна предполагаемая внешняя операция.

## Статусы карточки

```text
DRAFT -> READY_FOR_REVIEW -> APPROVED -> EXECUTED -> READ_BACK_VERIFIED
                              \-> REWORK
                              \-> BLOCKED
```

`APPROVED` означает одобрение конкретного текста и операции, а не постоянное
разрешение на будущие действия.

`repository_source` может быть `user_contract`, `project_card`,
`read_only_discovery` или `pending`. Для внешней записи источник должен быть
явно подтверждён; `current_workspace_origin` допускается только в
диагностической записи, не в качестве write-target.

Перед write-gate также требуется отдельное `target_confirmation:
user_confirmed`. Это подтверждает именно репозиторий, а не содержание issue.

## Граница текущего шага

Этот документ описывает локальный процесс. Он не утверждает, что NaCl-граф
подключён или что данные были сохранены в графе. Graph Mode задаёт порядок
ветвления, а VS Code tasks будут только исполнительными рельсами после того,
как формат карточки проверен.
