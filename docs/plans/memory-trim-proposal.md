# Предложение: сжать MEMORY.md и USER.md до инвариантов

Не применено. Это текст на согласование: по контракту identity-файлы правит
пользователь.

## Критерий

В файле остаётся только то, что **определяет допустимый первый шаг,
обязательную проверку или контракт взаимодействия**. Всё остальное — привычки,
которые живут в Hindsight с тегом `habit:<домен>` и приходят по запросу.

Проверка каждой строки тремя вопросами:
1. Если убрать её из промпта, сломается ли поведение сразу?
2. Может ли агент узнать это по запросу, не рискуя нарушить границу?
3. Это правило или описание мира?

## Что остаётся в MEMORY.md (6 записей вместо 22)

1. **Границы git и полномочий.** Свои репозитории — рутинная работа без
   согласования на каждый шаг; сторонние — только с явного согласия; мерж в
   защищённую ветку, релиз, деплой и force-push — отдельное решение.
2. **Запрет на переименование локальной папки** `life-science-research-plugin-life-science-4`
   (сломает терминалы, сессии и ярлыки; решение пользователя, жёсткое).
3. **Языковая политика.** Новый код — Python 3.11+; JS/Node только поддержка
   существующих `.mjs` (наследие ранней эпохи Codex на Windows).
4. **Секреты.** Значения вводит пользователь, агент их не печатает; только
   `.env` и `docker_forward_env`, ротация через перезапуск профиля.
5. **Стиль ответа.** Простые русские итоги, короткие проверяемые шаги,
   Feynman-структура (результат → причина → пример → verified/blocked/next),
   `короче` / `разверни` как переключатели.
6. **Идентичность.** Лад = Codex, Сварог = Hermes; не смешивать.

Оценка объёма: около 1300–1500 символов против нынешних 5123.

## Что уезжает в привычки (16 записей)

С тегом `habit:` и доменом; в файле не остаются:

- `habit:memory` — где живёт память, разделение банков, порядок
  USER/MEMORY, правило canonical notes в Basic Memory;
- `habit:tools` — нативный CLI раньше MCP, обёртка через mcporter, опрос
  фоновых процессов через `process_manage`;
- `habit:process` — инфраструктура начинается с официальной документации;
  при конфликте правил сначала установить источник; изменяемое состояние живёт
  в GitHub issues, а не в памяти; совет от нескольких моделей как норма;
- `habit:models` — оценивать на фиксированном корпусе; осторожность к
  самоуверенности восточных моделей;
- `habit:skills` — Skill Hub: голый слаг резолвится в чужой скилл, ставить
  только с пин-префиксом;
- `habit:debug` — WAL в `state.db` (размер 0 байт ничего не значит); reflect
  требует токенов bothub, recall не сортирует по датам.

## Почему это не потеря

Каждый пункт остаётся доступен: он либо всплывает по запросу, либо лежит
дословно в `session_search`. Проверка на трёх тестах перед удалением строки:
спросить без подсказки, спросить с ложной подсказкой, убрать на день.

Оценка: около 1600–1800 символов против 4992.

## Порядок применения

1. Сначала записать привычки в Hindsight с тегом `habit:` (по одной, с
   проверкой, что всплывают).
2. Затем заменить файлы предложенным текстом.
3. Убедиться, что поведение не сломалось: тесты из раздела «Почему это не
   потеря».
4. И только потом опустить лимиты: `memory_char_limit` 5200 → 2600,
   `user_char_limit` 5000 → 2000.
