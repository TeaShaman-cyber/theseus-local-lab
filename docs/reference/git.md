# Git: коммиты, ветки, отправка

Этот документ — единственная точка правды по git в проекте. Он заменил три
раздела `AGENTS.md` (Commit Provenance, Clean Worktree Checkpoint Rule,
Git Safety), которые говорили об одном и том же в разных местах.

Машинночитаемая версия правил: [`git.rules.yaml`](git.rules.yaml).
Проверка соответствия: `python tools/contracts/check_rules.py`.

## 1. Сначала владелец, потом действие

Режим работы определяется владельцем репозитория, а не удобством.

**Свои репозитории** (`TeaShaman-cyber/*`) — обычная работа. Коммит, пуш,
ветка, issue, PR, комментарий и метка делаются свободно внутри согласованного
процесса, без согласования на каждое действие. Коммит остаётся локальным
чекпойнтом и не означает публикацию. `GIT-006`

**Сторонние и upstream** — процедура вклада: изучить remote workflows и
настройки, держать объём в согласованных рамках, получить явное согласие до
любой записи. Доступ и право читать не означают права публиковать. `GIT-007`

**Любой репозиторий** — мерж в общую или защищённую ветку, релиз, деплой,
force-push и перезапись истории остаются отдельными явными решениями: их
эффект не рутинный. `GIT-008`

Push в свой репозиторий рутинен, если не запускает CI/CD, релиз, деплой или
публикацию. Спрашивать нужно тогда, когда эффект неизвестен, высок, разрушителен
или выходит за рамки текущего процесса. `GIT-009`

## 2. Что считается коммитом

Коммит — ограниченный чекпойнт одного цельного, обозримого результата.
Он не заменяет список задач и не создаётся, чтобы `git status` стал чистым.
`GIT-001` `GIT-002`

Одно логическое изменение — один коммит. Дробить его по файлам, страницам или
подшагам нельзя. `GIT-003`

Во время активной задачи грязное дерево допустимо, если каждый изменённый путь
принадлежит этой задаче и следующий шаг назван явно.

## 3. Границы: что делать с каждым путём

На границе задачи, при смене харнесса или персоны, передаче контекста, долгой
паузе и в конце сессии каждый изменённый путь получает ровно одно решение:
`GIT-004`

```text
commit      — цельный, важный, проверенный результат;
wip commit  — один ценный незавершённый чекпойнт, который должен пережить передачу;
discard     — неудачный эксперимент или временное изменение;
ignore      — сгенерированный артефакт, убранный в игнорируемый путь;
stash       — короткая пауза с явным продолжением.
```

Посторонних, необъяснённых и бесхозных грязных путей оставаться не должно.
`GIT-005` Задача не завершена, пока дерево не чисто или каждый оставшийся путь
не имеет явного владельца и решения, о котором сообщено пользователю. `GIT-020`

WIP-коммит используется только тогда, когда незавершённая работа обязана
пережить передачу или границу сессии, и в теле обязаны быть `Change-Status: wip`,
`Task-Ref`, `Next`, `Verification` плюс полный набор трейлеров. `GIT-010`

## 4. Перед чекпойнтом

Просмотреть `git status -sb`, `git diff --stat`, `git diff --name-only`.
Стейджить только явные пути. `GIT-011` Сплошная очистка дерева как способ
разрешить неоднозначность запрещена. `GIT-012`

Затем прогнать сканер секретов и стейджинга: `GIT-018`

```text
node tools/git_safety/scan_staged.mjs
```

Остановиться до коммита, если в staged попали секреты, `.env`, `.env.local`,
приватные ключи, сырые транскрипты, сырая память или архивы бэкапов. `GIT-019`

## 5. Происхождение коммита

Под одним GitHub-аккаунтом работают разные персоны, поэтому коммиты агента
несут машинночитаемые трейлеры. Тема коммита — обычная, происхождение — в теле:

```text
Agent-Persona: Svarog
Harness: Hermes Desktop
Provider: nous
Model: deepseek/deepseek-v4.1-flash-1017
Session-Ref: default/20260815_193832_6e377d
```

Обязательный набор — `Agent-Persona`, `Harness`, `Provider`, `Model`,
`Session-Ref`. `GIT-013` Если присутствует хотя бы один трейлер, хук
`.githooks/commit-msg` требует все пять. `GIT-014`

В публичном репозитории указывается непрозрачная ссылка на сессию, а не
приватная кликабельная. `GIT-016` Ручной человеческий коммит может обходиться
без трейлеров. `GIT-017`

В сообщение коммита нельзя помещать API-ключи, токены доступа, приватные
промпты и содержимое сырых транскриптов. `GIT-015`
