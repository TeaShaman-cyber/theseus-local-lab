# Операции: локальная среда

Как работать с оболочкой, службами и защищёнными файлами конфигурации. Заменил
две секции `AGENTS.md` — Shell And Services и User Codex Config Guard.

Машинночитаемый набор: [`operations.rules.yaml`](operations.rules.yaml).
Проверка: `python tools/contracts/check_rules.py`.

## 1. Оболочка

Выбор инструмента идёт от задачи, а не от привычки. Сначала **нативный CLI**,
если он есть: он предсказуем, версионируется вместе с инструментом и не требует
отдельного слоя. MCP подключается только тогда, когда даёт то, чего у CLI нет,
и шумные серверы не держатся экспонированными постоянно — обёртка через
`mcporter` возвращает в контекст только результат. VS Code tasks, WSL и
небольшие проверенные хелперы равноправны, а не являются правилом по умолчанию.
Длинные команды PowerShell остаются последним средством. `OPS-001`

Оболочка Codex, обычный пользователь Windows, Docker Desktop, WSL, VS Code и
виртуальные машины — **разные контексты**, пока исполнение не доказало обратное.
`OPS-002`

## 3. Конфигурация Codex

`%CODEX_HOME%/config.toml` — защищённая граница рантайма. Готовить файл-кандидат
вне живого пути, а замену делать только через репозиторный guard. `OPS-004`
`OPS-005`

```text
node tools/codex_config/config_guard.mjs --check --candidate <candidate.toml>
node tools/codex_config/config_guard.mjs --apply --candidate <candidate.toml>
```

Guard запускает `codex --strict-config doctor --json` в изолированном временном
`CODEX_HOME`, печатает только коды статуса, сохраняет резервную копию для
отката и выполняет постпроверку. `OPS-006`

Провал предпроверки не меняет живой файл. Провал постпроверки восстанавливает
предыдущий конфиг. `OPS-007`

Если guard или исполняемый файл Codex недоступны — остановиться до касания
живого файла. `OPS-008`

Прямые правки живого конфига Codex не являются одобренным рабочим процессом.
`OPS-009`
