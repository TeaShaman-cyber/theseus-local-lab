# Операции: локальная среда

Как работать с оболочкой, службами и защищённой конфигурацией Hermes.

Машинночитаемый набор: [`operations.rules.yaml`](operations.rules.yaml).
Проверка: `python tools/contracts/check_rules.py`.

## 1. Оболочка

Выбор инструмента идёт от задачи, а не от привычки. Сначала **нативный CLI**,
если он есть: он предсказуем и не требует отдельного слоя. MCP подключается
только тогда, когда даёт то, чего у CLI нет; шумные серверы вызываются через
`mcporter`, чтобы возвращать в контекст только результат. VS Code tasks, WSL и
небольшие проверенные хелперы равноправны. Длинные команды PowerShell остаются
последним средством. `OPS-001`

Hermes terminal, обычный пользователь Windows, Docker Desktop, WSL, VS Code и
виртуальные машины — **разные контексты**, пока исполнение не доказало обратное.
`OPS-002`

## 3. Конфигурация Hermes

`%HERMES_HOME%/config.yaml`, plugin selection и skill selection — защищённые
границы активного профиля. Менять их только штатным Hermes CLI, а не прямой
правкой файлов. `OPS-004`

Для плагинов сначала использовать `hermes plugins ...`; для настроек —
`hermes config set`; для скиллов — `hermes skills config` или проверенный
config fallback, если интерактивный маршрут недоступен. `OPS-005`

После изменения читать обратно точную цель через `hermes config get`,
`hermes plugins list` или `hermes skills list`; успешный exit code без read-back
не доказывает результат. `OPS-006`

Провал предпроверки не должен менять активный профиль. Если частичное изменение
произошло, восстановить предыдущее явно прочитанное значение и повторить
read-back. `OPS-007`

Если штатный менеджер заблокирован, назвать причину и использовать только
узкий проверяемый fallback, сохраняющий тот же профиль и семантику. Рабочий
fallback не становится новым маршрутом по умолчанию. `OPS-008`

Нельзя редактировать `config.yaml`, plugin registry или skill registry вручную.
`OPS-009`
